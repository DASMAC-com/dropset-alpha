# codama-idl-gen

Generates a [Codama IDL](https://github.com/codama-idl/codama) JSON file from the
instruction macro metadata defined in `dropset-interface`.

The IDL is produced entirely from trait impls generated by `#[derive(ProgramInstruction)]`
and `#[derive(CodamaType)]` — no source file parsing or manual type registration is needed.

## Usage

```sh
# Output to codama-idl-gen/idl.json (default):
cargo run -p codama-idl-gen

# Output to a custom path (relative to workspace root):
cargo run -p codama-idl-gen -- custom-output.json

# Output to an absolute path:
cargo run -p codama-idl-gen -- /tmp/idl.json
```

## Generating a TypeScript client

After generating the IDL, use [Codama's JS renderer](https://www.npmjs.com/package/@codama/renderers-js)
to produce a TypeScript client. Configuration lives in `codama.json` at the workspace root
(pointing to `codama-idl-gen/idl.json` as input and `codama-idl-gen/js/` as output).

```sh
# 1. Generate the IDL from the Rust macro metadata:
cargo run -p codama-idl-gen

# 2. Generate the TypeScript client from the IDL:
pnpm dlx codama run --all

# Generated TS output is in codama-idl-gen/js/:
ls codama-idl-gen/js/
```

The generated TypeScript includes typed instruction builders, encode/decode helpers,
and type definitions for all instruction arguments — using `@solana/kit`.

## How it works

1. `#[derive(CodamaType)]` on structs (e.g. `OrderInfoArgs`) generates a `CodamaType` impl
   that describes the struct's fields as a Codama
   [StructTypeNode](https://github.com/codama-idl/codama/blob/main/packages/nodes/docs/typeNodes/StructTypeNode.md).

2. `#[derive(ProgramInstruction)]` on the instruction enum generates a `CodamaProgram` impl
   that produces the full IDL tree:
   [InstructionNode](https://github.com/codama-idl/codama/blob/main/packages/nodes/docs/InstructionNode.md)s
   with accounts, arguments, and
   [discriminators](https://github.com/codama-idl/codama/blob/main/packages/nodes/docs/discriminatorNodes/ConstantDiscriminatorNode.md).

3. Custom argument types (unknown to the macro) are automatically collected from instruction
   variants and included as
   [DefinedTypeNode](https://github.com/codama-idl/codama/blob/main/packages/nodes/docs/DefinedTypeNode.md)s.
   If a type doesn't implement `CodamaType`, a compile error is produced.

4. This binary calls `DropsetInstruction::codama_root()`, serializes the result, and writes
   the JSON file. The binary itself contains no IDL logic — it just materializes the output
   from the proc macro.

## Adding new types

- **Struct with `#[derive(Pack)]`:** Add `#[cfg_attr(feature = "codama", derive(instruction_macros::CodamaType))]`.
- **Manual `Pack` impl (e.g. `UnvalidatedOrders`):** Manually implement `CodamaType` and
  add a `codama_defined_type()` method. See `interface/src/instructions/orders.rs` for an example.
