# codama-idl-gen

Generates a [Codama IDL](https://github.com/codama-idl/codama) JSON file from
the instruction macro metadata defined in `dropset-interface`.

The IDL is produced entirely from trait impls generated by
`#[derive(CodamaType)]` and `#[derive(CodamaProgram)]`.

## Usage

```sh
# Output to codama-idl-gen/idl.json (default):
cargo run -p codama-idl-gen

# Output to a custom path (relative to workspace root):
cargo run -p codama-idl-gen -- custom-output.json

# Output to an absolute path:
cargo run -p codama-idl-gen -- /tmp/idl.json
```

## Generating a TypeScript client

After generating the IDL, use [Codama's JS renderer] to produce a TypeScript
client. Update the [Codama configuration] if desired, then run the renderer with
it.

```sh
# 1. Generate the IDL from the Rust macro metadata:
cargo run -p codama-idl-gen

# 2. (Optional) Generate `codama.json`. It must point to the generated IDL json.
cd codama-idl-gen && pnpm dlx codama init

# 3. Then generate the TypeScript client from the IDL:
pnpm dlx codama run --all

# With the given `codama.json` config, view the generated TypeScript output at:
ls codama-idl-gen/js/
```

## How it works

1. `#[derive(CodamaType)]` on structs (e.g. `OrderInfoArgs`) generates a
   `CodamaType` impl that describes the struct's fields as a Codamaj
   [StructTypeNode](https://github.com/codama-idl/codama/blob/main/packages/nodes/docs/typeNodes/StructTypeNode.md).

2. `#[derive(CodamaProgram)]` on the instruction enum generates a
   `CodamaProgram` impl that produces the full IDL tree:
   [InstructionNode](https://github.com/codama-idl/codama/blob/main/packages/nodes/docs/InstructionNode.md)s
   with accounts, arguments, and
   [discriminators](https://github.com/codama-idl/codama/blob/main/packages/nodes/docs/discriminatorNodes/ConstantDiscriminatorNode.md).

3. Custom argument types (unknown to the macro) are automatically collected from
   instruction variants and included as
   [DefinedTypeNode](https://github.com/codama-idl/codama/blob/main/packages/nodes/docs/DefinedTypeNode.md)s.
   If a type doesn't implement `CodamaType`, a compile error is produced.

4. This binary calls `DropsetInstruction::codama_root()`, serializes the result,
   and writes the JSON file. The binary itself contains no IDL logic — it just
   materializes the output from the proc macro.

## Adding new types

- **Derived**
  - `#[derive(CodamaType)]`
  - `#[cfg_attr(feature = "codama", derive(CodamaType))]`
- **Manual:** See `UnvalidatedOrders` in [`orders.rs`] for an example.
